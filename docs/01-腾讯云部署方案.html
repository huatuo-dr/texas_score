日常发版（核心）：
cd /path/to/texas_score
git pull
./scripts/deploy.sh
脚本自动完成：安装依赖 → 构建 dist → 同步到 /var/www/texas-score →（可选）重载 Nginx。
与 ai-suan 的差异： ai-suan 使用 GitHub Actions 在云端 build 再 SSH 同步； 本项目不配置 CI 自动流水线，由你在服务器上主动 git pull 后执行部署脚本，流程更可控、依赖更少。

2目录约定

路径用途
/opt/texas_score Git 仓库工作副本（源码 + 构建）。可用其它路径，下文以此为例。
/var/www/texas-score Nginx 站点根目录，只放构建产物（与 ai-suan 的 /var/www/ai-suan 并列）。
/etc/nginx/... 站点配置（sites-available / conf.d）。

参考你现有习惯：ai-suan 在 /var/www/ai-suan； 德州记分建议 /var/www/texas-score，避免互相覆盖。

发布目录可用环境变量覆盖： DEPLOY_DIR=/var/www/texas-score ./scripts/deploy.sh

3服务器一次性准备

3.1 已有条件

  • 腾讯云轻量服务器，已安装并使用 Nginx
  • SSH 可登录；具备配置 Nginx 与写站点目录的权限

3.2 安装 Node.js（仅构建用）

构建需要 Node 20+。安装后不需要用 pm2/systemd 常驻跑前端。

# 示例：使用 NodeSource 安装 Node 20（Ubuntu/Debian）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

node -v   # 期望 v20.x
npm -v

若已用 nvm / fnm，确保登录 shell 下 node/npm 可用即可。

3.3 可选工具

sudo apt-get install -y git rsync
# rsync 用于同步 dist；未安装时脚本会回退到 cp

3.4 创建站点目录

sudo mkdir -p /var/www/texas-score
# 建议让部署用户可写，避免每次 rsync 都 sudo
sudo chown -R "$USER:$USER" /var/www/texas-score

4首次部署

  1. 克隆仓库到服务器 目录可自定，建议固定路径便于以后操作 
sudo mkdir -p /opt
sudo chown "$USER:$USER" /opt   # 若需要
git clone <你的仓库地址> /opt/texas_score
cd /opt/texas_score
chmod +x scripts/deploy.sh
  1. 配置 Nginx 按 §7 添加站点配置并 nginx -t && reload（首次需先有 conf，否则只有文件没有入口）
  1. 执行一键部署 安装依赖、构建、同步到 Nginx 目录 
cd /opt/texas_score
./scripts/deploy.sh
  1. 浏览器验证 打开配置的域名或 http://公网IP:端口

首次若 Nginx 尚未配置，脚本仍会成功写出 /var/www/texas-score，但外网访问要等 conf 生效。

5日常更新（你只需要两步）

cd /opt/texas_score
git pull
./scripts/deploy.sh

说明：

  • git pull：拉取最新代码（含前端改动与脚本本身）
  • ./scripts/deploy.sh：重新构建并覆盖 Nginx 目录中的旧 dist
  • 一般不必手动改 Nginx，除非改了端口/域名配置

构建会短暂占用 node_modules 与磁盘；产物同步后，对外服务只依赖 /var/www/texas-score，无需常驻 Node。

6自动化脚本 scripts/deploy.sh

脚本做什么

  1. 定位项目根目录不依赖当前 cwd
  2. 检查 node / npm缺失则报错退出
  3. npm ci无 lock 时回退 npm install
  4. npm run build生成 dist/
  5. 同步到 DEPLOY_DIR默认 /var/www/texas-score，rsync --delete
  6. nginx -t && reload可用环境变量关闭

环境变量

变量默认说明
DEPLOY_DIR /var/www/texas-score Nginx 站点根目录
RELOAD_NGINX 1 设为 0 则只同步文件、不 reload 
# 示例：自定义发布目录且不重载 Nginx
DEPLOY_DIR=/var/www/texas-score RELOAD_NGINX=0 ./scripts/deploy.sh

权限说明

  • 若当前用户对 DEPLOY_DIR 可写：直接 rsync
  • 若不可写：脚本会尝试 sudo rsync / sudo mkdir
  • reload Nginx 需要 sudo（与常见生产环境一致）

仓库路径：scripts/deploy.sh（已 chmod +x）。 克隆后若无执行权限：chmod +x scripts/deploy.sh。

7Nginx 配置（一次性）

风格可对齐 ai-suan：独立 conf + 独立站点目录。下面两种任选其一。

仓库内配置模板

完整示例已入库： deploy/nginx-texas-score.conf.example。 服务器上可： 

sudo cp /opt/texas_score/deploy/nginx-texas-score.conf.example /etc/nginx/conf.d/texas-score.conf
sudo vim /etc/nginx/conf.d/texas-score.conf   # 改 server_name
sudo nginx -t && sudo systemctl reload nginx

7.1 子域名（推荐）

# 例如 /etc/nginx/sites-available/texas-score
# 或 /etc/nginx/conf.d/texas-score.conf

server {
    listen 80;
    server_name poker.your-domain.com;   # ← 改成你的域名

    root /var/www/texas-score;
    index index.html;

    # 入口 HTML 禁止长缓存：发版后旧 index 会引用已删除的 /assets/* hash 文件 → 白屏/404
    location = /index.html {
        add_header Cache-Control "no-cache";
    }

    location / {
        try_files $uri $uri/ /index.html;
    }

    # 带 content hash 的构建产物可长缓存
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 无 hash 的站标等（按需）：短缓存或 no-cache
    # location = /favicon.svg {
    #     add_header Cache-Control "no-cache";
    # }

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
}
sudo ln -s /etc/nginx/sites-available/texas-score /etc/nginx/sites-enabled/  # 若用 sites-available
sudo nginx -t && sudo systemctl reload nginx

7.2 独立端口（快速验证，类似 http://IP:8088）

server {
    listen 8088;
    server_name _;

    root /var/www/texas-score;
    index index.html;

    location = /index.html {
        add_header Cache-Control "no-cache";
    }

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}

腾讯云安全组需放行对应端口。与 ai-suan 的 80/443 域名站点可同时存在。

缓存原则：/assets/* 可长期缓存； index.html 必须可被重新校验（no-cache）， 否则 rsync --delete 删掉旧 JS 后，仍持旧 HTML 的用户会白屏。

注意 root 层级

项目典型 root
ai-suan/var/www/ai-suan/dist（文档约定）
texas_score /var/www/texas-score（脚本直接把 dist 内容同步到该目录，目录内即是 index.html）

不要写成 root /var/www/texas-score/dist，除非你改脚本把文件同步到子目录 dist。

8域名与 HTTPS

部署本身不强制 HTTPS。记分与 localStorage 在 HTTP 下通常可用。 若希望手机端「系统分享」（如 navigator.share）稳定可用，建议上 HTTPS； 仅用 IP+端口验证功能时，HTTP 即可。 

# DNS：A 记录 poker → 服务器公网 IP
# 安全组：放行 80、443

# HTTP 通了之后：
sudo certbot --nginx -d poker.your-domain.com

大陆服务器域名 80/443 通常需 ICP 备案；未备案可先用 IP+端口。

静态站无服务端会话配置，上 HTTPS 后一般无需改前端代码。

场景协议建议
本机/IP 端口自测记分 HTTP 即可
正式给朋友用、依赖系统分享 HTTPS + 域名

9与 ai-suan 同机共存

项目代码/构建Nginx 目录发布方式
ai-suan （按原方案） /var/www/ai-suan GitHub Actions 等
texas_score /opt/texas_score /var/www/texas-score git pull + ./scripts/deploy.sh
  • 不同 server_name 或不同端口，互不抢 conf
  • 德州记分不引入 Docker，不占用 DB
  • 服务器上 Node 仅用于构建德州记分，不要求为前端起常驻进程

10验收与常见问题

验收

  • 执行 ./scripts/deploy.sh 无报错，日志显示部署完成
  • ls /var/www/texas-score 可见 index.html 与 assets/
  • 浏览器打开站点，记分功能正常；刷新数据仍在
  • 再次改代码后 git pull && ./scripts/deploy.sh 页面更新

FAQ

Q：构建很慢 / npm 超时？
可在服务器配置镜像：npm config set registry https://registry.npmmirror.com 后再跑脚本。

Q：permission denied 写 /var/www？
sudo chown -R $USER:$USER /var/www/texas-score，或让脚本走 sudo rsync。

Q：nginx -t 失败？
文件通常已同步；先修 conf，再 sudo systemctl reload nginx。也可 RELOAD_NGINX=0 ./scripts/deploy.sh 跳过 reload。

Q：要不要 GitHub Actions？
不需要。本方案刻意不引入 CI；由你在服务器手动 pull + 脚本发布。

Q：node_modules 会不会一直占空间？
会保留在 /opt/texas_score 以便下次构建更快。若磁盘紧张，可在确认发布成功后删除 node_modules，下次脚本会重新 npm ci。
