起手牌 13×13
胜率热力图方案

在「德州记分」工具中增加翻前起手牌（Starting Hands）13×13 热力图， 用于朋友局快速查阅「这手大概有多强」。纯前端静态展示，不做实时蒙特卡洛引擎。

v0.3 审查合入

钉死 equity 口径（6 人、5 对手随机、翻前 all-in 到河、chop、无 rake）； 唯一数据来源=仓库脚本生成 + meta； S/A/B/C/D 按 equity 分位切分；四 Tab 窄屏约定； 默认选中 AA；百分比「约 x.x%」一位小数；页脚合规半句； 与 docs/02 交叉引用。

1背景与目标

1.1 背景

现有「牌力」Tab 解决的是摊牌五张牌型序（同花顺 > 四条…）。 现场另一类高频问题是翻前：「AA 很强、AKs 怎么样、72o 有多差」—— 对应的是两张底牌起手牌的相对强弱，业界常用 13×13 矩阵热力图表达。

1.2 目标

  • 提供可读的 13×13 起手牌热力图（竖屏可用）。
  • 单元格能识别：对子 / 同花 / 不同花，以及相对强弱（色阶）。
  • 点击（或长按）单元格可查看该手的名称与说明（可选展示参考胜率/档位）。
  • 与记分、牌型序、术语一样：查阅向、无后端、不影响记分数据。

1.3 非目标（本版）

  • 实时输入任意手牌做精确 equity 计算。
  • 多人桌动态人数切换后重算全部矩阵（可二期）。
  • GTO 策略、开池范围编辑器、训练刷题。

2概念说明（给产品对齐用）

2.1 13×13 是什么

德州底牌忽略具体花色后，有 169 种策略等价手牌。 用 13 点（A,K,Q,J,T,9…2）做行列，可铺成矩阵：

  • 对角线：对子 AA, KK, …, 22
  • 上三角（或一侧）：同花 AKs, AQs, …（s = suited）
  • 下三角（或另一侧）：不同花 AKo, AQo, …（o = offsuit）

单元格颜色表示「相对强弱」或「参考胜率档位」，故称热力图。

2.2 「胜率」在本产品中的含义（必须写清，避免误解）

重要免责语义

本图展示的是预计算、固定假设下的近似 equity， 不是当前这一手实时胜率，也不是「该不该玩」的建议。 UI 页头必须有说明，避免当成计算器精确结果。

2.2.1 Equity 精确定义（生成数据前写死 · P0）

项定义（不可偏离）
胜负口径 翻前 all-in 到河牌 的 equity；平分底池按 chop（平分期望）计入。
对手模型 其余 5 人各持均匀随机的合法手牌（与自己不冲突发牌）。
人数 正好 6 人入池（含自己）。
Rake 不含抽水。
单位 该手在摊牌的期望分得底池比例，数值 ∈ (0, 1)；UI 展示为百分比。

页头标准句式（可微调措辞，语义不可少）：

页头免责文案

示意：6 人桌，其余 5 人随机手牌，翻前全下到河的近似 equity，仅供朋友局参考， 不是实时胜率，也不是建议你该不该玩。

2.3 与「牌力」Tab 的差异

牌力 Tab（已有）本热力图（拟做）

3与现有功能关系

当前全局 Tab：记分 | 牌力 | 术语。热力图是第四块查阅能力，入口有三种放法（见 §4）。

  • 不读写 useScoreStore，不改持久化结构。
  • 部署仍为静态资源；发版 git pull && ./scripts/deploy.sh。
  • 切换 Tab 时继续遵守：离开记分 blur / 关确认与分享弹层。

  • 切换 2/6/9 人实时重算整表（二期：多套预置表切换）。
  • 格子内显示完整百分数（太挤）；详情区可显示一位小数百分比或「档位」。
  • 导出图片分享（可 P1）。

6数据模型与来源

6.1 唯一真相来源（P0 写死）

唯一来源

使用仓库内离线脚本按 §2.2.1 口径生成 169 格数据， 产物提交为 src/data/preflopMatrix.ts（或等价 JSON 再 export）。 不以手写表或未标注出处的第三方文件为并行真相； 若参考公开算法/实现，须在 meta.source 写明并保证脚本可复现。

  • 脚本路径建议：scripts/generate-preflop-matrix.mjs（或 .ts + 文档说明运行方式）。
  • 生成结果必须入库，运行时只读常量，用户端不执行模拟。
  • meta 至少包含：players、source、version、口径摘要、tierBreaks。

6.2 Equity 与展示格式

  • 存储：equity ∈ (0, 1)，禁止 0/1 贴边与 NaN（模拟应极难出现 0/1，若出现需审查）。
  • UI 百分比：统一 「约 x.x%」一位小数（例：0.342 →「约 34.2%」）；详情与 aria-label 同格式。

6.3 档位 S/A/B/C/D（生成阶段写死）

着色主用 equity 连续色阶；tier 仅作标签，不得另搞一套与 equity 矛盾的色阶。 档位在生成脚本中按全局 169 手 equity 分位切分并写入每个 cell（阈值记入 meta.tierBreaks）：

档位规则（P0 默认，生成后可微调分位但须写入 meta）
Sequity 最高约 5% 的手（约 8～9 手）
A其后约 10%
B中上约 20%
C中下约 30%
D其余

同分位边界：equity 降序稳定排序后切段；同 equity 按 code 字典序保证可复现。

6.4 数据形状

{
  ranks: ['A','K','Q','J','T','9','8','7','6','5','4','3','2'],
  meta: {
    players: 6,
    opponents: 5,
    model: 'random_uniform_hole_cards',
    equityDefinition: 'preflop_allin_to_river_chop_no_rake',
    source: 'scripts/generate-preflop-matrix.mjs',
    version: '1',
    tierBreaks: { /* 生成时写入的分位或阈值说明 */ },
    disclaimer: '近似参考，非实时胜率'
  },
  // row===col pair; row<col suited; row>col offsuit
  cells: HandCell[][]  // 13x13
  // HandCell:
  {
    code: 'AKs',
    kind: 'pair' | 'suited' | 'offsuit',
    equity: 0.342,
    tier: 'S' | 'A' | 'B' | 'C' | 'D'
  }
}

6.5 冒烟断言（CI / 单测必跑）

  • 维度 13×13，169 格齐全；无 NaN；每格 equity ∈ (0,1)。
  • AA.equity > KK.equity > QQ.equity。
  • AKs.equity > AKo.equity；AKs.equity > AQs.equity。
  • 全局 max 为 AA（或并列时含 AA）；72o 位于最弱分位（如 D 且 equity 接近最小）。
  • 对角线全为 pair；上三角 suited、下三角 offsuit。
  • 每个 cell 的 tier 与 meta.tierBreaks 规则一致（或与生成快照一致）。

7界面与交互

7.1 页面结构（自上而下）

  1. 全局 Tab（记分 | 牌力 | 术语 | 胜率）
  2. 页头标题 + §2.2.1 免责/假设说明
  3. 色阶图例（横条：弱 → 强；主映射 equity）
  4. 矩阵（主视觉）
  5. 详情卡：默认选中 AA；展示 code、类型、约 x.x%、档位
  6. 页脚半句合规提示（见下）

7.2 四 Tab 窄屏约定（P0）

  • 文案短：「胜率」两字已定；四 Tab 不换行、不缩成纯图标。
  • 可略降 font-size / 收紧 letter-spacing。
  • 每个 Tab 热区高度 ≥ 40px。

7.3 矩阵交互与格子文案

  • 点击选中并保持（避免误触清空）；选中描边高亮 + 详情更新。
  • 默认选中 AA，首屏详情非空。
  • 格子文案：对子 AA；同花 AKs；不同花 AKo；整表缩字优先一屏宽，尽量避免双轴滚动。
  • 极窄屏：完整名称靠 aria-label；可见文案可再压缩但不可去掉可达性信息。
  • 触控：单元格尽量 ≥ 约 22–28px。

7.4 与壳层一致性

  • 无记分底栏；无「一手」工具条；无底栏 padding。
  • 进入该 Tab 时滚动置顶。
  • 切 Tab 继续清理确认框/分享弹层（与记分实现一致）。

7.5 无障碍

  • 矩阵 role="grid" / gridcell；aria-label 含手牌、约 x.x%、档位。
  • 详情区可用 aria-live="polite"。

8色阶与图例

  • 着色唯一依据：equity 连续映射；tier 不参与主色阶（避免两套矛盾）。
  • 冷色（弱）→ 暖色（强）；暗色主题保证对比度。
  • 对子可加细描边，方便扫对角线。
  • 图例：弱 ────── 强 +「颜色越暖，参考 equity 越高」。
  • 色盲友好：选中态用描边，不只靠颜色。

9技术实现建议

  • 组件：PreflopHeatmapPanel.tsx + 矩阵 + 详情；默认 state 选中 AA。
  • 数据：scripts/generate-preflop-matrix.* 生成 → src/data/preflopMatrix.ts 入库。
  • 着色：equityToColor(e) 纯函数；formatEquityPct(e) => '约 34.2%'。
  • Tab：AppTabId 增加 'preflop'；标签「胜率」；四列窄屏样式见 §7.2。
  • 性能：169 格静态 DOM 即可。
  • 测试：§6.5 冒烟 + UI 选中 AA/AKs 详情含 % 与 tier + 免责文案 + 切 Tab 不丢记分。

11验收标准

  • 可进入「热力/起手/胜率」查阅页，竖屏可完整操作矩阵（允许字号缩小）。
  • 矩阵为 13×13；能区分 pair / suited / offsuit。
  • 颜色随强弱变化；有图例。
  • 点击格子，详情显示正确 code、类型、约 x.x%（一位小数）与 S/A/B/C/D。
  • 默认选中 AA；详情非空。
  • 页头含 §2.2.1 口径说明；页脚含合规半句。
  • 矩阵上三角 s、下三角 o、对角线 pair；§6.5 冒烟断言通过。
  • meta.source / version 存在；着色仅依赖 equity。
  • 四 Tab 窄屏不换行；该页无记分底栏；回记分数据仍在。
  • 构建与测试通过。
