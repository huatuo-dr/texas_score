德州扑克记分工具
初版产品与技术方案

面向手机竖屏场景的本地单页记分工具：记录买入/剩余，自动计算盈亏， 支持校验、排序与结果图片分享。数据仅存浏览器本地，不依赖云端。

1概述

家庭局 / 朋友局德州扑克结束后，需要快速统计每人买入筹码、剩余筹码与盈亏， 并核对全场筹码是否守恒。本工具提供现场可操作的记分面板， 以「手」为可配置的加减步长单位，在手机上完成录入、校验与结果分享。

核心公式
结果(盈亏) = 剩余 − 买入
校验合计 = Σ 结果　　　期望值：0
总筹码　 = Σ 买入
总人数　 = 人员列表长度

允许买入、剩余、结果出现负数，以兼容纠错与特殊记账场景。界面与文档统一使用「买入」，不再使用「总数」。

2目标与边界

2.1 初版目标

  • 手机竖屏下一屏完成「加人 → 记买入 → 记剩余 → 看盈亏 → 校验 → 分享」。
  • 关闭页面后再次打开，当前场次数据不丢失（浏览器本地存储）。
  • 交互简单、触控友好：大按钮、少层级、危险操作有确认。
  • 窄屏底栏自适应，避免五个操作键挤在一行。

2.2 设计原则

  • 本地优先：无账号、无服务器、无云同步。
  • 可纠错：数值可手改、可负数；不因「不合理」强拦截正常改数。
  • 整数记账：买入、剩余、「一手」均为整数，禁止小数与非法字符。
  • 可解释：校验不仅显示是否为 0，还显示差额及多码/少码含义。
  • YAGNI：初版不做历史场次、不做云端、不做撤销栈、不做转账结算方案。

4业务规则

4.1 数值与输入规则

  • 买入、剩余、结果均允许负数。
  • 强制整数：买入、剩余、「一手」配置只接受整数；禁止 1.5、abc、3%! 等非法内容。
  • 非法输入不写入状态（过滤或拒绝），不得落库脏值。
  • 编辑中允许暂时为空，避免输入过程被强制改写打断；失焦时若为空串或无法解析为整数 → 规范为 0。
  • 仅输入 - 等中间态：编辑中可暂留；失焦无法解析为整数则 → 0。
  • 粘贴含小数或非数字内容：不接受为有效非整数（按非法处理）。
  • +/− 步进始终在整数上按当前「一手」加减。
  • 结果始终由公式计算：remain - buyIn；加载后以公式重算为准。

4.2 「一手」配置规则

  • 配置项名称：一手对应筹码数量（简称「一手」）。
  • 合法范围：正整数，最小值 1；非法输入时提示并回退到上一次合法值。默认 2000。
  • 修改「一手」后：
    • 已有人员的买入、剩余、结果保持不变；
    • 此后点击买入旁的 + / −，按新的一手数量增减；
    • 此后新添加人员的默认买入与默认剩余 = 新的一手数量（结果为 0）；
    • 此后执行清空记分时，买入与剩余均重置为新的一手数量（结果为 0）。
  • 「一手」本身会持久化保存。

4.3 人员规则

  • 添加人员：
    1. 数据层：始终追加到人员数组末尾，分配新的 order（递增）；
    2. 默认：姓名为空（展示占位「未命名」）、买入 = 当前一手、剩余 = 当前一手；
    3. 结果 = 一手 − 一手 = 0（开局尚未产生盈亏）；
    4. 展示层：按当前 sortMode 排序后渲染（非强制插到视觉末尾）；
    5. 插入后立即 focus 该行姓名输入框（focus 对应数据行，不因排序找不到）。
  • 姓名允许暂时为空；分享图片时用「未命名」或「玩家 N」。
  • 初版不强制姓名唯一。
  • 删除单人：弹出二次确认 → 确认后从列表移除并持久化；不可撤销。

4.4 清空规则（两种）

操作 人员 买入 剩余 一手配置 确认
清空人员 全部删除 — — 保留 必须二次确认
清空记分 保留姓名 全部 = 当前一手 全部 = 当前一手 保留 必须二次确认
  • 两种操作确认后均不可撤销（不做 Undo）。
  • 确认文案示例：
    • 清空人员：「确定清空全部人员？此操作不可恢复。」
    • 清空记分：「确定清空全部记分？将保留人员，买入与剩余均重置为一手（结果归 0）。此操作不可恢复。」
    • 删除单人：「确定删除「{姓名}」？此操作不可恢复。」（姓名空则用「未命名」）
  • UI 入口：窄屏下位于「更多」菜单中的两项（或「清空」子选择 a/b）；宽屏可并列或同属清空分组。

4.5 校验规则

checksum = sum(player.result) // 即 sum(剩余 − 买入) = sum(剩余) − sum(买入)
  • checksum === 0：成功态，例如「校验通过，结果合计 = 0」。
  • checksum > 0：警示态，例如「账不平，结果合计 = {n}。剩余合计比买入多（多出来的筹码）。」
  • checksum < 0：警示态，例如「账不平，结果合计 = {n}。剩余合计比买入少（少了的筹码）。」
  • 校验不拦截后续编辑，仅提供反馈。
  • 建议在汇总区常驻显示「结果合计」，点击「校验」时加强提示（弹层 / Toast / 高亮）。

4.6 排序规则

  • 排序字段：结果（盈亏）。
  • 提供三种 sortMode：
    • manual / 原始顺序：按 order 升序（添加先后）；
    • result_desc：结果从大到小，赢家在上；
    • result_asc：结果从小到大。
  • 结果相同时：按 order 稳定排序，避免抖动。
  • 排序只影响展示顺序，不改写人员数组的逻辑追加顺序与字段值。
  • 在排序视图下添加成员：数据仍追加到数组末尾并赋予新 order；界面按当前 sortMode 重新排序后展示（新建人结果为 0，会落在 0 分段内）。

4.7 汇总指标

指标计算展示
总人数 人员条数 汇总区常驻
总筹码 Σ 买入 汇总区常驻
结果合计 Σ 结果 汇总区常驻 + 校验强化提示
一手 用户配置 配置区常驻

5界面与交互（竖屏）

5.1 信息架构

单页应用，自上而下分为四块：

  1. 顶栏：标题 + 一手配置

5.4 触控与布局要求

  • 优先视口宽度 ≤ 390px 的可用性；避免横向滚动成为主路径。
  • 可点击热区建议 ≥ 40px；+/− 按钮足够大，避免误触相邻输入。
  • 数字输入调用手机数字键盘（inputmode="numeric" 或等效），并在逻辑层强制整数。
  • 列表在窄屏下可采用「卡片式每人一行多行字段」，若四列表格过于拥挤； 信息字段顺序仍保持：姓名 → 买入 → 剩余 → 结果。

6数据模型

建议的逻辑结构（实现可用 TypeScript interface / 纯 JSON）：

{ "version": 1, // 存储结构版本，便于以后迁移 "unitPerHand": 2000, // 一手对应筹码数量（正整数，默认 2000） "sortMode": "manual", // manual | result_desc | result_asc "players": [ { "id": "uuid-or-nanoid", // 稳定主键 "name": "张三", "buyIn": 2000, // 买入（整数，可负） "remain": 2000, // 剩余（整数，可负） "order": 0 // 添加顺序，用于恢复原始排序 } ], "updatedAt": "2026-07-27T12:00:00.000Z" }
  • UI 文案统一为「买入」；内部字段推荐 buyIn（勿再命名/展示为「总数」）。
  • result 不作为权威存储字段，展示时计算：remain - buyIn。
  • 新人员默认：buyIn = unitPerHand，remain = unitPerHand（结果为 0）。
  • 清空记分：每人 buyIn = remain = unitPerHand，姓名与 id 保留。
  • 添加人员：数组末尾追加；列表渲染按 sortMode 排序。
  • version 用于日后字段变更时的兼容迁移。
  • 初版仅维护当前一场数据，不设 sessions 数组。

7本地持久化方案

结论

使用浏览器 localStorage（键名建议 texas_score_v1）持久化完整状态。 用户所说的「浏览器 cache」在本方案中落实为本地 Web 存储， 而非 HTTP Cache：关闭标签页 / 浏览器后再次进入同源页面，数据仍可恢复。

7.1 读写时机

  • 读：应用启动时加载；解析失败则回退到默认空状态，并避免写坏数据。
  • 写：任何状态变更后防抖写入（如 100–300ms），以及页面 visibilitychange / pagehide 时立即 flush，降低杀进程丢数风险。

7.2 容量与限制

  • 单场人员通常 < 20，数据量极小，localStorage 足够。
  • 无跨设备同步；清除站点数据会导致丢失——可在界面用一行小字提示「数据仅保存在本机浏览器」。
  • 隐私模式 / 部分 WebView 可能限制存储：写入失败时 Toast 提示，避免静默丢数。

7.3 明确不做

  • 不做云端账号与同步
  • 不做多设备协作
  • 不做服务端备份

8分享结果图片

8.1 目标

用户点击「分享结果」后，生成一张汇总图片，便于保存到相册或发到微信群等 IM。

8.2 图片内容（已定）

  • 标题：固定「德州记分」（不做局名/自定义标题）
  • 时间：生成时刻的本地时间
  • 元信息：一手、总人数、总筹码、结果合计（并标注是否账平）
  • 表格：姓名 | 买入 | 剩余 | 结果（结果带颜色或 +/- 符号）
  • 页脚：小字「仅供朋友局记账参考」

8.3 交互流程

  1. 点击「分享结果」（窄屏位于「更多」内）
  2. 将隐藏的「分享卡片」DOM 渲染为图片（或 Canvas 绘制）
  3. 优先尝试：
    • 支持 Web Share API 且可分享文件 → 调起系统分享；
    • 否则 → 预览图片 + 「长按保存 / 下载」。

8.4 实现备注

  • 可选库：html-to-image / html2canvas 等；需注意手机端字体与跨域图片问题（初版尽量纯色、系统字体，降低踩坑）。
  • 分享图使用独立布局（固定宽度，如 750px 逻辑宽），不直接截取可能横向拥挤的操作台 UI，保证出图清晰。

9技术建议

已定技术栈

Vite + React + TypeScript。 构建产物为纯静态文件，可部署至任意静态托管；无后端。

  • 样式：移动优先 CSS；可用轻量方案（纯 CSS / Tailwind），保持依赖简单。
  • 状态：单页状态集中管理；每次变更驱动重算汇总与持久化；展示列表由 players + sortMode 派生。
  • 测试：核心纯函数单测——结果计算、校验多/少码文案、排序、一手变更不影响已有买入、新人员默认（买入=剩余=一手）、清空记分重置、整数规范化、排序视图下添加仍追加到数据末尾。
  • 无后端：无 API、无数据库。

10非功能要求

  • 性能：人员 < 30 时交互瞬时响应；持久化防抖，避免频繁同步写。
  • 兼容：iOS Safari、Android Chrome 近两个大版本；微信内置浏览器可打开并记分（分享能力可能降级为下载/长按保存）。
  • 可访问基础：按钮有明确文案；错误有可见反馈。
  • 安全隐私：数据不出本机；无第三方统计 SDK（初版）。

12验收标准（初版）

  • 技术栈为 Vite + React + TypeScript 静态前端。
  • 手机竖屏下可完成完整记分流程，主操作无需横屏。
  • 一手默认 2000；可改；修改后仅影响之后的买入 +/−、新人员默认、清空记分重置。
  • 添加人员：数据末尾追加；默认买入=剩余=当前一手（结果 0）；按 sortMode 展示；focus 姓名。
  • 可修改姓名；删除单人、清空人员、清空记分均有二次确认。
  • 清空记分：保留人员，买入与剩余均重置为当前一手。
  • 买入可手输与 +/−；剩余可手输；结果只读且 = 剩余 − 买入。
  • 买入/剩余/结果均支持负数；输入强制整数，空串失焦归 0。
  • 结果 ≥0 绿色，<0 红色。
  • 总人数、总筹码（Σ买入）正确；校验区分账平 / 多码 / 少码。
  • 可按结果排序（含恢复原始顺序）；排序视图下新增仍追加到数据末尾。
  • 窄屏底栏为「添加 / 校验 / 更多」；宽屏可展示全部操作。
  • 关闭页面再打开，一手配置与人员数据仍在。
  • 分享图标题固定「德州记分」+ 本地时间，无局名；可预览/下载或系统分享。
  • 无云端依赖；无转账结算功能。
